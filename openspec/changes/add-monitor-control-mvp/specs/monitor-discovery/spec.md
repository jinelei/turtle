# Spec Delta

## Purpose

发现并管理通过 DDC/CI 可达的物理显示器：枚举设备、读取厂商/型号/序列号等身份信息，并在设备连接状态变化后重新枚举，为输入源切换与状态读取提供可靠的设备清单。

## ADDED Requirements

### Requirement: 枚举支持 DDC/CI 的显示器

系统 SHALL 枚举当前主机连接的所有物理显示器，并对每台显示器建立 DDC/CI 通信会话。设备清单 MUST 包含稳定的内部标识、平台句柄以及用户可识别的显示名称。

#### Scenario: 正常枚举到多台显示器

- **WHEN** 应用启动或用户触发刷新，且主机连接了 2 台开启 DDC/CI 的显示器
- **THEN** 显示器列表展示 2 台设备，每台带有可识别名称与唯一内部标识

#### Scenario: 没有连接任何显示器

- **WHEN** 主机未连接外接显示器（如 Mac 合盖仅用内建屏）
- **THEN** 界面展示空状态与"未检测到支持 DDC/CI 的显示器"提示，且不发生崩溃

### Requirement: 读取显示器身份信息

系统 SHALL 为每台显示器读取并展示身份信息，至少包括厂商名称、型号名称与序列号；身份信息 MUST 优先来自 EDID / 平台显示 API，无法取得的字段允许为空但必须以"未知"明确标注，不得展示为乱码或原始字节。

#### Scenario: 读取 Lenovo P27h-20 身份信息

- **WHEN** 枚举到一台 Lenovo P27h-20 显示器
- **THEN** 信息面板展示厂商"Lenovo"、型号"P27h-20"，序列号字段展示设备序列号或"未知"

#### Scenario: EDID 中部分字段缺失

- **WHEN** 显示器 EDID 中未写入序列号
- **THEN** 序列号位置展示"未知"，厂商与型号仍正常展示

### Requirement: 重新枚举以反映热插拔变化

系统 SHALL 提供手动刷新入口，并在显示器连接或断开后给出设备列表已变化的提示；后续所有操作 MUST 基于最新枚举结果执行，指向已消失设备的操作 MUST 被拒绝并返回明确错误。

#### Scenario: 运行中断开一台显示器

- **WHEN** 用户刷新设备列表前某台显示器已被拔掉
- **THEN** 刷新后列表不再包含该设备；若用户此前已选中它，界面提示"显示器已断开"并要求重新选择

#### Scenario: 对已失效的设备句柄执行操作

- **WHEN** 设备列表刷新后，用户对已不存在的内部标识发起输入源切换
- **THEN** 操作被拒绝，返回"设备不存在或已断开"错误，且不向任何其他显示器发送 VCP 指令
